Qué analiza, y con qué

Cuatro tipos de análisis distintos, cada uno mira una capa diferente del sistema. Ninguno reemplaza a los otros.

SAST Static Application Security Testing

Lee el código fuente sin ejecutarlo. Encuentra patrones peligrosos antes de que lleguen a producción: uso de eval(), SQL construido por concatenación, clientes AWS sin timeout, secretos hardcodeados.

Bandit SonarQube Community
SCA Software Composition Analysis

Audita las dependencias de terceros que tu proyecto instala. Un eval() propio se corrige en una línea; un RCE conocido en una dependencia transitiva de tu toolchain de deploy no siempre.

npm audit pip-audit
DAST Dynamic Application Security Testing

Ataca el endpoint real en ejecución, como lo haría alguien externo: fuzzing de headers, inyección, vectores conocidos. Es el único de los cuatro que requiere una URL — y esa URL nunca se asume.

OWASP ZAP
API Top 10 OWASP API Security (2023)

Los diez puntos que ninguna herramienta automatizada cubre por completo: BOLA, autenticación rota, asignación excesiva de propiedades, consumo de recursos, exposición de inventario. Requiere leer el código de los handlers — se documenta como pass / falla / parcial con evidencia.

Revisión guiada

Lo que nunca hace sin preguntar

Un scanner automatizado que corre en tu repo puede hacer daño si actúa solo. Este no actúa solo.

→
No corrige dependencias sin confirmar

npm audit fix modifica package-lock.json y puede romper tu build. Siempre se pregunta antes de correrlo.

→
No asume la URL del DAST

Un active scan de OWASP ZAP envía payloads de ataque reales. La URL target y el ambiente (dev/staging, nunca producción sin luz verde) se confirman siempre con vos.

→
No hace commit por su cuenta

El reporte y los hallazgos pueden contener rutas internas o datos sensibles. Se pregunta antes de subir nada a git.

→
Se degrada con gracia

Si no tenés Docker, corre igual Bandit + npm/pip audit sin fricción. SonarQube y ZAP quedan como opt-in cuando los necesitás.
